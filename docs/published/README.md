# Documentation Index

Welcome to the published documentation for the **Personal Full-Stack Portfolio** project.

This documentation serves as the project's permanent knowledge base. It captures the project's vision, software engineering practices, architectural decisions, implementation history, and technical references.

The documentation is organized by purpose to make information easy to locate and maintain.

---

## Core Reference Documents

These documents define the project and provide the foundation for all development activities.

| Document                | Purpose                                                                                                   |
| ----------------------- | --------------------------------------------------------------------------------------------------------- |
| `PROJECT.md`            | Defines the project's vision, goals, scope, architecture, roadmap, and guiding principles.                |
| `PROJECT_MANAGEMENT.md` | Defines the project's development workflow, implementation process, and project management practices.     |
| `GLOSSARY.md`           | Defines project terminology and commonly used technical concepts referenced throughout the documentation. |

---

## Technical Documentation

These documents evolve as the project is implemented.

| Directory     | Purpose                                                                                         |
| ------------- | ----------------------------------------------------------------------------------------------- |
| `adr/`        | Architectural Decision Records documenting significant technical decisions and their rationale. |
| `api/`        | API documentation and endpoint references.                                                      |
| `deployment/` | Deployment guides and infrastructure documentation.                                             |
| `milestones/` | Published milestone summaries documenting completed development milestones.                     |

---

## Private Documentation

Project planning notes, conversation summaries, and other working documents are maintained separately under `docs/private/`.

These files support development but are intentionally excluded from version control because they are not part of the project's permanent documentation.

---

## Documentation Principles

This documentation follows several guiding principles:

* Every document has a single, well-defined responsibility.
* Documentation describes completed work rather than anticipated work.
* Significant architectural decisions are captured as Architectural Decision Records (ADRs).
* Milestone summaries document implementation progress.
* Project documentation evolves alongside the application while remaining organized and maintainable.
